# Mini Git 구현 해설과 핵심 개념

먼저 `README.md`의 실행 예시를 직접 입력한 다음, 이 문서를 **함수 이름을 검색하며** 읽으면 됩니다. 코드는 `main.py` 한 파일에 있어 호출 관계를 따라가기 쉽습니다.

## 1. 전체 실행 흐름

```text
python main.py
  └─ main(): MiniGit() 생성
      └─ 반복: input("mini-git> ")
          └─ MiniGit.execute(line)
              ├─ shlex.split(): 명령어와 인자 분리
              ├─ 명령어를 대문자로 바꿔 분기
              ├─ 상태/인자 검증
              ├─ 저장소·그래프·정렬·검색 함수 실행
              └─ 결과 문자열 반환
          └─ print(): 화면 출력
      └─ exit/quit 또는 EOF → 종료
```

- **함수**는 이름을 붙인 동작 단위입니다. `execute()`는 명령을 해석하고 관련 작업을 호출하는 진입점입니다.
- **객체**는 데이터와 동작을 함께 다룹니다. `git = MiniGit()`은 현재 저장소의 상태를 가진 객체를 만듭니다.
- `self`는 그 객체 자신을 가리킵니다. 예: `self.branches`는 해당 저장소의 브랜치 사전입니다.
- **REPL**은 Read(입력) → Evaluate(실행) → Print(출력) → Loop(반복)의 약자입니다.
- `shlex.split()`은 쉘과 비슷하게 따옴표 안의 공백을 하나의 인자에 남깁니다. 따라서 `COMMIT "Add login"`은 메시지 한 개이고, 따옴표 없이 `COMMIT Add login`을 입력하면 두 인자이므로 `Invalid args`입니다.
- `execute()`의 반환값 `None`은 종료 신호입니다. 빈 문자열 `""`은 출력하지 않는 공백 입력이며, 오류 문자열은 프로그램이 종료되지 않고 출력합니다.

## 2. 저장소 상태: dict, list, set, tuple

처음 배우는 Python 자료형부터 다음 순서로 구분하세요.

| 자료형 | 의미 | 사용 위치 |
| --- | --- | --- |
| `dict`(사전) | 키 → 값 찾기 | `commits[hash]`, `branches[name]`, 인덱스 |
| `list`(목록) | 순서 있는 여러 값 | 정렬 대상, 그래프 탐색 결과 |
| `set`(집합) | 중복 없는 값, 빠른 포함 검사 | 역색인에 속한 커밋 hash, DFS 방문 집합 |
| `tuple`(튜플) | 변경하지 않을 값의 묶음 | `Commit.parents` |
| `deque`(양방향 큐) | 맨 앞에서 빠르게 꺼내는 구조 | BFS 및 위상 정렬 대기열 |

`MiniGit.__init__()`의 상태는 다음처럼 시작합니다.

```python
self.user = None
self.current_branch = None
self.branches = {}
self.commits = {}
self.keyword_index = {}
self.author_index = {}
```

`None`은 값이 없다는 뜻입니다. `INIT Alice`를 호출하면 다음 상태가 됩니다.

```text
user = "Alice"
current_branch = "main"
branches = {"main": None}
commits = {}
```

여기서 **브랜치는 커밋 자체가 아니라 특정 커밋을 가리키는 이름**입니다. `BRANCH feature`는 현재 브랜치가 가리키는 hash를 `branches["feature"]`에 복사할 뿐, 기존 커밋을 복제하지 않습니다. `SWITCH feature`는 `current_branch`만 바꾸고, 기존 커밋을 삭제하거나 재작성하지 않습니다.

`INIT` 재호출은 저장소 상태를 모두 비우지만 `next_number`는 유지합니다. 따라서 한 실행 세션에서 이전에 발급된 hash를 다시 쓰지 않습니다.

## 3. 커밋과 DAG

### 정의

- **노드(node)**: 데이터 한 개. 여기서는 `Commit` 하나입니다.
- **간선(edge)**: 노드 간 연결. 여기서는 `child.parents`가 부모 커밋을 가리킵니다.
- **방향 그래프**: 간선 방향이 있는 그래프. `자식 → 부모` 방향입니다.
- **DAG(Directed Acyclic Graph)**: 방향성이 있으면서 사이클(출발한 노드로 다시 돌아오는 경로)이 없는 그래프입니다.

`@dataclass(frozen=True)`가 붙은 `Commit`은 `hash`, `message`, `author`, `timestamp`, `parents` 필드를 갖고, 생성 후 필드를 바꿀 수 없습니다. `timestamp`는 UTC 기준 ISO 8601 문자열입니다. `hash`는 `next_number`를 16진수 문자열로 표현한 **학습용 식별자**이며 Git의 암호학적 SHA 해시가 아닙니다.

### COMMIT 처리 (`MiniGit.create_commit`)

1. 카운터를 증가시켜 새 hash를 얻습니다.
2. `branches[current_branch]`를 조회하여 부모를 정합니다. 첫 커밋이면 부모가 없습니다.
3. `Commit`을 만들고 `commits[hash]` 사전에 추가합니다.
4. 현재 브랜치의 포인터를 새 hash로 바꿉니다.
5. 메시지·작성자 역색인을 동시에 갱신합니다.

```text
INIT Alice → COMMIT root → BRANCH feature
                          ├─ main: 00000001
                          └─ feature: 00000001
SWITCH feature → COMMIT side
                          ├─ main: 00000001
                          └─ feature: 00000002 → 부모 00000001
SWITCH main → COMMIT other
                          ├─ main: 00000003 → 부모 00000001
                          └─ feature: 00000002 → 부모 00000001
```

이 구현에서 새로운 커밋은 **이미 존재하는 현재 HEAD**를 부모로만 가리킵니다. 따라서 미래 커밋을 부모로 가리킬 수 없고 사이클도 생기지 않습니다. `MERGE` 명령은 제외했으므로 CLI에서 생성되는 커밋은 부모가 0개 또는 1개입니다. 하지만 `parents`가 튜플이기 때문에 알고리즘 자체는 부모가 여러 개인 DAG에도 적용할 수 있습니다.

## 4. LOG: 부모 우선 출력과 위상 정렬

### 정의

**위상 정렬**은 DAG의 선행 관계를 지키는 나열입니다. 이 미션에서는 실제 Git의 보통 로그처럼 최신순이 아니라 **모든 부모가 해당 자식보다 먼저** 출력돼야 합니다.

### 동작 (`topological_log`)

1. 각 커밋에 남아 있는 부모 수(`remaining_parents`)를 기록합니다.
2. 부모 → 자식 방향의 임시 `children` 사전을 만듭니다. 실제 저장 구조인 자식 → 부모를 탐색 용도에 맞게 뒤집는 것입니다.
3. 부모가 0개인 커밋을 `deque`에 넣습니다.
4. 큐 앞에서 꺼내 출력하고, 그 커밋을 부모로 둔 자식들의 남은 부모 수를 1씩 감소시킵니다.
5. 부모 수가 0이 된 자식을 큐 뒤에 넣고 반복합니다.

이것이 **Kahn 알고리즘**입니다. `deque.popleft()`는 앞에서 꺼내는 데 평균 O(1)이지만 `list.pop(0)`은 뒤 원소를 이동해야 하므로 O(n)입니다. 전체 비용은 커밋 수 `V`, 부모 간선 수 `E`에 대해 **O(V + E)**입니다.

`LOG --sort-by=date|author`는 위상 정렬이 아니라 **별도의 기준 정렬**입니다. 날짜나 작성자순 로그에서는 부모 우선 조건을 강제하지 않습니다. 두 요구를 구분하세요.

## 5. PATH: 무방향 최단 경로와 BFS

### 정의

**경로**는 간선을 따라 이동한 노드들의 순서이고, 여기서 **최단 경로**란 지나간 간선 수가 최소인 경로입니다. 부모 간선 `자식 → 부모`를 **양방향**으로 이동할 수 있다고 간주합니다. 이 때문에 같은 부모에서 갈라진 두 커밋 사이에도 `자식 → 부모 → 다른 자식` 경로가 존재합니다.

### 동작 (`shortest_path`)

1. 각 부모 연결을 양쪽 `neighbors`에 기록합니다.
2. 시작 노드를 `deque` 큐에 넣고 BFS(너비 우선 탐색)를 수행합니다.
3. 노드를 꺼내면 인접 노드를 **hash 사전순**으로 확인합니다.
4. 처음 방문한 노드의 직전 노드를 `previous[neighbor] = current`로 기억합니다.
5. 목표에 도착하면 `previous`를 역추적하고 경로를 뒤집습니다.

BFS는 거리 0, 1, 2, …인 노드를 차례대로 방문하므로 **첫 방문 경로가 최단**입니다. 인접 노드를 hash 사전순으로 확인하므로 같은 길이의 경로 중 `hash1->hash2->...`를 사전순으로 비교했을 때 가장 작은 경로를 우선 선택합니다. 이 프로그램의 hash는 16진수 문자로 구성되며 경로 구분자 `->`는 고정되어 있습니다.

경로가 없으면 `No path`, 없는 hash이면 `Unknown commit: ...`입니다. 서로 부모가 없는 독립된 커밋도 만들 수 있습니다. 예를 들어 커밋 전 `BRANCH orphan`을 만든 뒤 `main`, `orphan`에서 각각 첫 커밋을 만들면 둘은 연결되지 않습니다.

BFS 자체는 **O(V + E)**, 인접 노드를 직접 구현한 병합 정렬로 정리하는 비용을 포함하면 상한은 **O(V + E log V)**입니다.

## 6. ANCESTORS: DFS와 방문 집합

### 정의

**DFS(깊이 우선 탐색)**는 한 방향으로 최대한 따라간 뒤 다른 경로를 살펴보는 탐색입니다. **스택(stack)**은 마지막에 넣은 값을 먼저 꺼내는 LIFO 구조입니다. Python `list.append()`/`list.pop()`으로 구현할 수 있습니다.

### 동작 (`find_ancestors`)

- 대상의 부모들을 스택에 넣고 시작합니다.
- 스택에서 부모를 하나 꺼냅니다. 처음 보는 부모만 `found` 집합에 기록하고 그 부모의 부모를 스택에 넣습니다.
- 스택이 빌 때 종료합니다. 시작 커밋 자체는 결과에 포함하지 않습니다.

`found`는 병합형 DAG에서 같은 조상을 여러 경로로 만나도 중복 처리를 막습니다. 재귀가 아닌 반복문을 사용하므로 깊은 체인에서 Python 재귀 깊이 제한을 피합니다. 탐색 대상의 조상 부분 그래프에 대해 **O(Va + Ea)**입니다. 출력 시에는 해당 hash 목록만 `merge_sort`로 정렬합니다.

## 7. SEARCH: 역색인 두 종류

### 순회 검색과 역색인 차이

모든 커밋을 훑어 키워드를 비교하면 검색할 때마다 전체 `N`개 커밋을 검사해야 합니다. **역색인(inverted index)**은 먼저 `단어 → 그 단어를 가진 커밋 hash의 집합`을 저장하므로 찾을 후보만 가져올 수 있습니다.

커밋 메시지 `"Add login login"`을 저장할 때:

```text
message.lower().split() → ["add", "login", "login"]
set(...)               → {"add", "login"}
keyword_index          → {"add": {"00000001"}, "login": {"00000001"}}
author_index           → {"Alice": {"00000001"}}
```

- `SEARCH login`: `keyword_index["login"]`에서 후보 hash를 바로 가져옵니다.
- `SEARCH "add login"`: `add`와 `login`의 집합 교집합을 만들고, 그 **후보의 메시지만** 검사하여 단어 순서까지 확인합니다.
- `SEARCH --author=Alice`: `author_index["Alice"]`에서 후보 hash를 가져옵니다.
- 검색 결과는 후보 목록만 `merge_sort`로 정리합니다. **전체 커밋을 훑는 `LOG` 함수를 검색에 사용하지 않습니다.**

사전·집합 평균 조회는 O(1)이고, 한 단어 검색의 기본 비용은 후보 건수 `K`에 비례합니다(출력 정렬을 포함하면 O(K log K)). 여러 단어 검색은 게시 목록(posting list)의 교집합과 후보 메시지 검사 비용이 추가됩니다. 인덱스 구축 비용과 메모리를 쓰는 대신 반복 검색이 빨라지는 **시간-공간 트레이드오프**입니다.

> 메시지 검색은 공백 단어 단위입니다. 예를 들어 `login`은 `login`을 찾지만 `logins`를 찾는 부분 문자열 검색은 아닙니다. 대소문자는 구분하지 않고, 문장부호는 단어에서 자동 제거하지 않습니다.

## 8. LOG --sort-by: 안정 병합 정렬

### 정의

**정렬**은 값을 비교 기준(키)에 따라 나열하는 과정입니다. `merge_sort`는 배열을 반씩 나눈 뒤 각각 정렬해서 합치는 **분할 정복** 알고리즘입니다.

```text
[4, 1, 3, 2]
    ↙       ↘
 [4, 1]   [3, 2]
 [4] [1]  [3] [2]
    ↘       ↙
 [1, 4]   [2, 3]
       [1, 2, 3, 4]
```

`merge_sort(items, key)`의 `key`는 항목에서 비교할 값을 추출하는 함수입니다. 날짜 정렬은 `commit.timestamp`, 작성자 정렬은 `commit.author.lower()`를 비교합니다.

두 값의 키가 같을 때 `<=`로 **왼쪽 항목을 먼저** 넣습니다. 따라서 원래 상대 순서가 유지되는 **안정 정렬(stable sort)**입니다. 입력 목록을 바꾸지 않고 새 목록을 반환합니다.

| 알고리즘 | 평균 시간 | 최악 시간 | 추가 공간 | 안정 정렬 |
| --- | --- | --- | --- | --- |
| 구현한 병합 정렬 | O(n log n) | O(n log n) | O(n) | 예 |
| 삽입 정렬(대안) | O(n²) | O(n²) | O(1) | 예(일반적 구현) |
| 퀵 정렬(대안) | 평균 O(n log n) | O(n²) | 구현에 따라 다름 | 보통 아니오 |

병합 정렬은 최악에도 O(n log n)을 유지하기 때문에 선택했습니다. 단, 병합용 추가 목록이 필요합니다. 미션 제한에 따라 `sorted()`나 `list.sort()`를 사용하지 않습니다.

## 9. 설계상의 경계와 선택

- **해시**: Git SHA가 아니라 단순 증가 카운터를 16진수로 표시합니다. 충돌하지 않는 식별자라는 필수 목적을 충족하지만 파일 내용의 동일성 검증 기능은 없습니다.
- **HEAD**: 실제 Git의 `HEAD` 파일 대신 `current_branch`와 `branches[current_branch]`의 조합으로 나타냅니다.
- **작성자**: CLI에서 작성자는 `INIT`으로 설정하고 `INIT`은 저장소를 초기화합니다. 따라서 지원하는 명령만 사용하면 한 저장소의 작성자는 보통 한 명이며 `--sort-by=author`는 동률 정렬이 됩니다. 알고리즘은 여러 작성자 값을 정렬할 수 있고 단위 테스트는 객체의 작성자 값을 바꾸어 그 경우를 검증합니다. 별도 작성자 변경 명령은 미션에 없으므로 추가하지 않았습니다.
- **브랜치 전환**: 실제 Git처럼 작업 디렉터리를 체크아웃하지 않습니다. 파일을 추적하지 않는 메타데이터 프로그램이기 때문입니다.
- **영속성**: 저장은 메모리에만 합니다. 프로그램을 종료하면 상태가 사라집니다.
- **보너스 제외**: `DIFF`, `MERGE`, 정렬 성능 비교를 넣지 않았습니다. 단, 부모가 여럿인 **인위적인 그래프**를 단위 테스트에 넣어 탐색 함수의 일반성은 확인했습니다.

## 10. 핵심 함수 호출 관계

| 동작 | 실제 함수 | 주요 상태/알고리즘 |
| --- | --- | --- |
| 모든 명령의 시작 | `main()` → `MiniGit.execute()` | REPL, 파싱, 유효성 검사 |
| 초기화 | `MiniGit.initialize()` | 저장소와 인덱스 재설정 |
| 브랜치 | `MiniGit.execute()`의 `BRANCH`, `SWITCH` 분기 | `branches`, `current_branch` |
| 커밋 | `MiniGit.create_commit()` | `Commit`, 부모 튜플, 두 역색인 |
| 부모 우선 로그 | `topological_log()` | Kahn 위상 정렬 |
| 날짜·작성자 로그 | `merge_sort()` | 안정 병합 정렬 |
| 최단 경로 | `shortest_path()` | 무방향 BFS, 사전순 인접 노드 |
| 모든 조상 | `find_ancestors()` | 스택 DFS, 방문 집합 |
| 키워드 검색 | `MiniGit.search_keyword()` | 역색인 교집합, 후보만 검사 |
| 작성자 검색 | `MiniGit.execute()`의 `SEARCH` 분기 | 작성자 역색인 직접 조회 |
| 결과 형식 | `MiniGit.format_commits()` | hash, 작성자, 시각, 메시지 |
